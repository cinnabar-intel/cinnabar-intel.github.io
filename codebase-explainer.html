01 / split

Two engines, one point of view

The important boundary is between intake and publication.

The weekly public scan and the reusable NotebookLM scaffold solve adjacent problems. Knowing which one you are touching prevents a lot of wrong turns.

Engine A · operational

The editorial intelligence loop

A scheduled Claude research session scans trusted sources, appends defensible signals, updates the current dispatch, and opens a reviewable pull request.

  • scripts/run-weekly-scan.sh
  • weak-signal-watch.md
  • digest/src/pages/index.astro
  • deploy-docs.yml
Engine B · reusable scaffold

The NotebookLM processing lane

A Python template turns YouTube, RSS, or one-off URLs into normalized items, persisted state, NotebookLM notebooks, intel cards, and artifact records.

  • pipeline/main.py
  • pipeline/db.py

  • pipeline/cli.py
02 / loop

The weekly scan

Every Monday, the machine turns a reading list into a reviewable argument.

The scan is intentionally branch-first. Research can be ambitious; publication still passes through human review.

From source window to shipped dispatch

systemd → Claude → GitHub Pages
01 / triggerSystemd timerMonday 00:30 UTC. Persistent catch-up handles a sleeping machine.
02 / scanClaude researchReads the prompt, searches 16 Tier-2 sources, and classifies signals.
03 / writeKnowledge + digestAppends the evidence log and optionally rewrites the current issue.
04 / reviewPull requestBranches, commits, pushes, and creates a PR. Never master directly.
05 / shipPages deployCI builds MkDocs and Astro, then merges both into one site artifact.
Human gate: source quality, profile, category, countGraceful degrade: audio may fail without blocking the dispatch
03 / signal

The product is the profile

A signal is not just “interesting.” It gets a visible, debatable shape.

The knowledge system replaces a single score with five dimensions. That makes uncertainty legible and keeps the publication honest about what is known.

E3 · T-Ac · U4 · H-Gr · Z-Now

Example signal profile. Evidence is early, trajectory is accelerating, unlock is high, hype is grounded, and impact is actionable now.

Where the profile is defined
knowledge-system/design/05-signal-scoring-framework.md defines the rubric and the “uncommon but likely” filter.
EEvidenceHow real is it? Deployment, data, or theory?
TTrajectoryEmerging, accelerating, maturing, or shifting?
UUnlockWhat becomes possible only because of it?
HHype gapGrounded, ahead, peak hype, or post-hype?
ZHorizonNow, near, medium, or far?

05 / scaffold

Inside the Python lane

A small async pipeline with durable state.

The scaffold is designed for idempotent reruns: collect once, deduplicate in SQLite, retry failed items, and keep NotebookLM work isolated per source.

07 / truth

Reality check

The map is useful because it shows the unfinished edges too.

These are the implementation details worth holding in your head before extending the system.

gap

Artifact records are not local downloads.

The NotebookLM wrapper can download artifacts, but the parallel generation path currently records notebooklm:// references instead of writing files.

gap

The digest is editorial, not database-driven.

The current Astro issue is authored as a page. The weekly prompt keeps it synchronized with the Markdown signal log.

watch

Citations are still being repaired.

The citation policy is explicit, but parts of the signal log and sidecars still contain TODO URLs.

strength

The human gate is part of the design.

Scans branch, commit, and open a PR. Research can move quickly without silently publishing to master.

08 / next

If you are extending it

Three questions to ask before adding code.

Is this a content change, an automation change, or a rendering change?
Content belongs in knowledge-system/. Operational behavior belongs in scripts/. Public page structure belongs in digest/. NotebookLM ingestion belongs in assets/project-template/.
Does the change preserve the evidence chain?
New claims should remain traceable to a source, carry the signal profile when appropriate, and preserve the citation rules described in 04-system-methodology.md.
Can the system recover from a partial run?
The intended answer is yes: SQLite state, dated branches, retryable failed items, scan locks, and graceful audio failure all exist to make partial progress recoverable.
The machine is a point-of-view compiler.

Source material in. Auditable judgment out.
